# 项目实现说明

更新日期：2026-06-04

## 1. 项目定位

本项目是一个个人主页式的互动网站，表现形式是“我的小世界地图”。访客先看到欢迎页，点击开始后进入世界地图，再点击地图上的建筑进入不同主题房间。

当前网站不是后端项目，也没有数据库。所有页面内容、房间信息、建筑位置和展示文案都在前端代码里维护。

## 2. 技术栈

- 构建工具：Vite
- 前端框架：React
- 样式：原生 CSS
- 图片处理脚本：Node.js + sharp
- 静态资源目录：`public/assets`

关键配置：

- `package.json`：定义运行、构建、预览脚本。
- `vite.config.js`：启用 React 插件。
- `index.html`：页面 HTML 壳，挂载 React 根节点 `#root`。

## 3. 页面流程

页面状态由 `src/App.jsx` 统一控制。

当前有三个场景：

| 场景 | 状态值 | 组件 | 说明 |
| --- | --- | --- | --- |
| 欢迎页 | `welcome` | `WelcomeScene` | 展示开始背景和开始按钮 |
| 世界地图 | `map` | `WorldMap` | 展示地图、建筑、房间入口 |
| 房间详情 | `room` | `RoomDetail` | 展示当前房间主题、说明和卡片内容 |

切换逻辑：

- 点击欢迎页按钮后，`startGame()` 把场景从 `welcome` 切到 `map`。
- 点击地图建筑后，`enterRoom(roomId)` 记录当前房间 ID，并进入 `room`。
- 点击详情页返回按钮后，`returnToMap()` 回到地图并清空当前房间。

过渡动画通过 `transitionName` 控制，最终体现在 `app-shell transition-*` 这些 CSS class 上。

## 5. 入口文件

### `src/main.jsx`

负责创建 React 根节点，把 `App` 挂载到 `index.html` 里的 `#root`。

### `src/App.jsx`

负责全局页面状态：

- `scene`：当前场景。
- `activeRoomId`：当前进入的房间 ID。
- `transitionName`：当前过渡动画名称。

它不直接维护房间内容，而是从 `src/data/rooms.js` 读取配置。

## 6. 数据配置

房间数据集中维护在 `src/data/rooms.js`。

每个房间包含：

- `id`：房间唯一标识。
- `title`：房间英文标题。
- `label`：地图上展示的中文名称。
- `subtitle`：房间副标题。
- `mapHint`：地图 hover 提示文案。
- `accentColor` / `secondaryColor`：房间主题色。
- `asset`：建筑图片路径。
- `position`：建筑在地图上的位置。
- `items`：房间详情页展示的卡片内容。

新增房间时，优先在这里加配置，再补充对应图片素材。

## 7. 组件说明

### `WelcomeScene.jsx`

欢迎页组件，负责展示：

- 背景图 `public/assets/welcome/final-start-background.png`
- 标题 `Welcome to My Little World`
- 开始按钮图片 `public/assets/welcome/enter-island-board.png`

点击开始按钮后调用父组件传入的 `onStart`。

### `WorldMap.jsx`

世界地图组件，负责展示：

- 地图底图 `public/assets/world/second-map-base.png`
- 建筑入口按钮
- hover 时的建筑名称和说明
- 摆位模式

摆位模式说明：

- 点击右上角“摆位”后进入编辑模式。
- 可以拖动地图上的建筑。
- 新位置会写入浏览器 `localStorage`，key 是 `opc-world-map-room-positions-v1`。
- 摆位面板会展示每个房间的 `left`、`top`、`width`、`zIndex`。

注意：摆位模式保存的是浏览器本地数据，不会自动写回 `src/data/rooms.js`。如果要把摆位结果变成正式代码，需要手动复制面板里的位置，更新 `rooms.js`，并记录到变更文档。

### `RoomDetail.jsx`

房间详情组件，负责展示：

- 返回地图按钮
- 房间主题视觉区
- 房间标题、副标题
- `items` 里的卡片列表

房间视觉区复用当前房间的建筑图片，并通过 `accentColor`、`secondaryColor` 控制颜色风格。

### `Buildings.jsx`

该文件保留了部分早期手绘 SVG 建筑组件和 `buildingComponents` 映射，但当前页面主流程没有引用它。当前地图建筑展示使用的是 `rooms.js` 中的图片素材路径。

如果后续不用 SVG 建筑，可以考虑删除该文件；如果要恢复 SVG 建筑，需要重新在 `WorldMap.jsx` 中接入。

## 8. 样式实现

全站样式集中在 `src/styles.css`。

主要样式模块：

- 全局变量和基础样式。
- 欢迎页背景、标题、开始按钮动画。
- 地图页海面、云、光点、HUD、建筑 hover 动效。
- 摆位模式样式。
- 房间详情页布局、房间内景、卡片样式。
- 页面切换动画。

维护原则：

- 修改页面视觉时优先改 `styles.css`。
- 修改展示内容时优先改 `rooms.js`。
- 修改页面流程时再改 `App.jsx` 或组件文件。

## 9. 静态资源

欢迎页资源：

- `public/assets/welcome/final-start-background.png`
- `public/assets/welcome/enter-island-board.png`
- 其他 welcome 目录图片为过程或备用素材。

地图资源：

- `public/assets/world/second-map-base.png`
- `public/assets/world/*.png`：各建筑图片。
- `public/assets/world/layers/`：图层拆分相关素材。

资源路径在 React 里以 `/assets/...` 开头引用，因为 Vite 会把 `public` 目录作为站点根路径。

## 10. 图层脚本

`scripts/create-world-layers.mjs` 使用 `sharp` 从源图中裁切图层，并生成预览图。

当前脚本输出：

- `start-journey-enter-island.png`
- `left-work-play-create-dream.png`
- `world-map-base-without-separated-assets.png`
- `layer-composite-preview.jpg`

这个脚本主要用于素材加工，不是页面运行必需逻辑。

## 11. 常见改动方式

### 新增房间

1. 把建筑图片放到 `public/assets/world/`。
2. 在 `src/data/rooms.js` 的 `rooms` 数组新增一项。
3. 设置 `id`、`label`、`asset`、`position`、`items`。
4. 本地运行检查地图入口和详情页。
5. 在 `docs/变更记录.md` 记录一次“新增”。

### 删除房间

1. 从 `src/data/rooms.js` 删除对应房间配置。
2. 确认没有其他组件引用该房间 ID。
3. 判断是否删除对应图片素材。
4. 本地运行检查地图和详情页。
5. 在 `docs/变更记录.md` 记录一次“删除”。

### 修改房间文案

1. 修改 `src/data/rooms.js` 中对应房间字段。
2. 本地检查地图提示和详情页卡片。
3. 在 `docs/变更记录.md` 记录一次“修改”。

### 修改建筑位置

1. 本地启动网站。
2. 进入地图页，点击“摆位”。
3. 拖动建筑到目标位置。
4. 复制摆位面板输出。
5. 更新 `src/data/rooms.js` 中对应 `position`。
6. 清理浏览器本地保存的位置后复核默认效果。
7. 在 `docs/变更记录.md` 记录一次“修改”。

### 查询现状

如果只是查看项目结构、运行方式、某个房间配置、某个素材来源，也要在 `docs/变更记录.md` 写“查询”记录，保留结论。

## 12. 后续维护规范

- 所有增删改查都要记录在 `docs/变更记录.md`。
- 不要只改代码不改文档。
- 不要把临时浏览器摆位当成正式代码。
- 页面内容优先配置化，避免把房间文案散落到组件里。
- 删除文件前先确认当前入口是否引用。
- 大改前先写清楚目标、范围和验证方式。
